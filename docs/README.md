# docs

| 폴더 | 내용 | 언제 쓰나 |
|---|---|---|
| `specs/` | 기능 사양서. "무엇을 어떻게 동작시키는가" | 기능 단위 개발마다 1개. 사양이 바뀌면 같은 파일을 갱신 |
| `intent-log/` | 의도 기록. LLM이 한 질문과 사용자의 답을 **원문 그대로** 남김 | 개발 세션마다 1개. 한 번 쓰면 수정하지 않음 (추가만) |

## 왜 둘을 나누나

- **사양서**는 결과물이고 계속 갱신된다. 다듬어진 문장이라 "왜 이렇게 됐는지"가 빠지기 쉽다.
- **의도 기록**은 원재료다. 사용자가 실제로 한 말과, LLM이 사용자 대신 정한 것(가정)을 구분해서 남긴다.
  나중에 리뷰어(사람이든 LLM이든)가 "이건 요구사항인가, 구현자의 임의 판단인가"를 판별할 수 있게 하는 게 목적.

## intent-log 작성 규칙

파일명: `YYYY-MM-DD-<주제>.md`

1. **Q&A** — LLM의 질문 요지와 사용자 답변 원문(인용). 답변은 다듬지 않는다.
2. **사용자가 명시하지 않아 LLM이 정한 것** — 기본값·가정과 그 이유. 리뷰 시 가장 의심해야 할 부분.
3. **결과** — 관련 사양서·PR 링크.
