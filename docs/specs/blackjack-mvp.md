# 블랙잭 MVP 사양

- 상태: 구현 완료 (v0.1.0)
- 의도 기록: [`intent-log/2026-10-11-blackjack-mvp.md`](../intent-log/2026-10-11-blackjack-mvp.md), [`intent-log/2026-10-11-ui-feel.md`](../intent-log/2026-10-11-ui-feel.md)

## 1. 목적

폰 브라우저에서 설치 없이 바로 켜서 혼자 즐기는 블랙잭.
카지노 표준 룰(더블·스플릿·보험·서렌더)을 갖추고, 주요 룰 차이(S17/H17, 3:2/6:5, 덱 수)를 설정에서 바꿔 볼 수 있다.

### 범위 밖 (이번에 하지 않은 것)

- 멀티플레이어, 서버, 계정
- 베이직 스트래티지 힌트, 카드 카운팅, 시뮬레이션
- 사이드 벳(퍼펙트 페어, 21+3 등)
- 사운드, PWA 오프라인 캐시(Service Worker)

## 2. 게임 흐름

```
betting ──deal──▶ (딜러 업카드 A?) ──yes──▶ insurance ──결정──▶ peek
                        │no                                      │
                        └──────────────────────────▶ peek ◀──────┘
peek: 딜러 BJ 또는 플레이어 BJ → settled
      그 외 → player (핸드별 액션) → 딜러 플레이 → settled
settled ──deal──▶ 다음 라운드
```

| 단계 (`Phase`) | 가능한 조작 |
|---|---|
| `betting` / `settled` | 칩(10·50·100·500) 추가, 지우기, 올인, 딜. 설정 변경 즉시 반영 |
| `insurance` | 보험(또는 이븐 머니) / 안 함 |
| `player` | 히트, 스탠드, 더블, 스플릿, 서렌더 |

- 딜 순서: 플레이어 → 딜러(업) → 플레이어 → 딜러(홀, 뒷면).
- 직전 베팅 금액은 다음 라운드에 유지된다. 잔액보다 크면 잔액에 맞춰 자동으로 줄인다.

## 3. 룰

### 3.1 핸드 값

- 2~10은 숫자대로, J·Q·K는 10, A는 1 또는 11.
- A 하나를 11로 세도 21 이하면 **소프트** 핸드. 화면에는 `7/17`처럼 두 값을 함께 표시한다(종료된 핸드는 큰 값만).
- **블랙잭(내추럴)**: 처음 두 장으로 21. 스플릿 후 핸드의 21은 블랙잭이 아니다.

### 3.2 딜러

- 업카드가 A 또는 10점이면 **피크**: 홀 카드로 블랙잭인지 확인하고, 블랙잭이면 즉시 정산.
- 16 이하는 히트, 17 이상은 스탠드.
  - **S17** (기본): 소프트 17에서도 스탠드.
  - **H17**: 소프트 17이면 히트.
- 플레이어 핸드가 전부 버스트/서렌더면 딜러는 카드를 더 받지 않는다.
- 플레이어 블랙잭(스플릿 없음)으로 끝난 라운드도 딜러는 카드를 더 받지 않는다.

### 3.3 플레이어 액션

| 액션 | 조건 | 동작 |
|---|---|---|
| 히트 | 활성 핸드 | 한 장 받음. 21 이상이면 핸드 종료 |
| 스탠드 | 활성 핸드 | 핸드 종료 |
| 더블 | 두 장, 잔액 ≥ 베팅, (스플릿 핸드면 DAS ON) | 베팅 2배, 한 장만 받고 종료 |
| 스플릿 | 두 장이 같은 **값**, 잔액 ≥ 베팅, 핸드 수 < 4 | 두 핸드로 분리하고 같은 금액을 추가 베팅. 각 핸드는 두 번째 카드를 받은 뒤 순서대로 진행 |
| 서렌더 | 서렌더 ON, 첫 핸드의 두 장(스플릿 전) | 베팅 절반 회수, 핸드 종료 |

- **A 스플릿**: 각 핸드는 한 장씩만 받고 자동 종료한다(리스플릿 불가).
- 어떤 핸드든 21이 되면 자동 스탠드.

### 3.4 보험 / 이븐 머니

- 딜러 업카드가 A일 때 제안한다. 비용은 베팅의 1/2이고, 잔액이 부족하면 버튼을 비활성화한다.
- 딜러가 블랙잭이면 보험은 2:1로 지급(원금 포함 3배 반환), 아니면 몰수하고 게임을 계속한다.
- 플레이어가 블랙잭이면 보험 대신 **이븐 머니**를 제안한다. 받으면 딜러 확인 없이 즉시 1:1(+1×)로 정산하고 라운드를 끝낸다. 비용이 없으므로 잔액과 무관하게 항상 선택할 수 있다.
  - 이븐 머니는 보험과 별개의 정산이다. 3:2에서는 "블랙잭 + 보험"과 결과가 같지만, 6:5에서는 "블랙잭 + 보험"이 +0.7×(+1.2 − 0.5)에 그치므로 같은 동작으로 취급하지 않는다.

### 3.5 정산 (반환액 = 원금 포함)

| 결과 | 반환 | 순손익 |
|---|---|---|
| 블랙잭 | 베팅 × (1 + 배당) | 3:2면 +1.5×, 6:5면 +1.2× |
| 이븐 머니 | 베팅 × 2 | +1× (배당 무관) |
| 승리 (딜러 버스트 포함) | 베팅 × 2 | +1× |
| 푸시 (동점, 양쪽 블랙잭) | 베팅 | 0 |
| 서렌더 | 베팅 × 0.5 | −0.5× |
| 패배 / 버스트 | 0 | −1× |

- 딜러 블랙잭일 때 플레이어 블랙잭은 푸시, 그 외는 패배.
- 라운드 순손익 = 반환 총액(보험 포함) − 이번 라운드에 건 총액(더블·스플릿·보험 포함).

### 3.6 슈

- `덱 수 × 52`장을 Fisher–Yates로 섞는다. 난수는 `crypto.getRandomValues`를 쓴다.
- 75% 소진되면 다음 라운드 시작 전에 리셔플하고 토스트로 알린다.
- 라운드 도중 슈가 바닥나면 즉시 리셔플한다(안전장치).

## 4. 설정

| 항목 | 선택지 | 기본값 |
|---|---|---|
| 덱 수 | 1 / 2 / 4 / 6 / 8 | 6 |
| 딜러 소프트 17 | S17 / H17 | S17 |
| 블랙잭 배당 | 3:2 / 6:5 | 3:2 |
| 서렌더 허용 | ON / OFF | ON |
| 스플릿 후 더블 (DAS) | ON / OFF | ON |
| 핸드 합계 표시 | ON / OFF | ON |
| 잔액 초기화 | 버튼 (라운드 사이에만) | — |

- 룰 변경은 **라운드 사이에만** 적용한다. 진행 중에 바꾸면 다음 딜부터 적용된다는 안내를 표시한다.
- 덱 수를 바꾸면 새 슈를 만든다.
- 설정 화면에 각 룰의 설명(한국어)을 넣는다.

## 5. 저장

- `localStorage` 키 `stand-on-17:v1` = `{ bankroll, bet, rules, showTotals }`.
- 잔액은 **라운드 경계(정산 후·베팅 중)의 값**만 저장한다. 진행 중에 설정을 바꾸면 설정은 즉시 저장하되, 잔액은 마지막 라운드 경계 값을 그대로 둔다.
- 그래서 진행 중에 새로고침하면 그 라운드 시작 전 잔액으로 돌아간다.
- 저장소에 접근할 수 없으면(프라이빗 모드 등) 저장 없이 동작한다.
- 시작 자금은 1,000. 최소 칩(10)보다 잔액이 적으면 "다시 시작" 버튼을 표시한다.

## 6. 화면 (모바일 우선)

- 최대 폭 560px. 위에서부터 헤더(잔액, 슈 잔량 바, 설정) / 테이블(딜러, 메시지, 플레이어 핸드) / 하단 조작부.
- 조작부는 엄지가 닿는 하단에 둔다.
  - 플레이 중 조작부 높이는 152px로 고정한다. 아래 줄은 히트·스탠드, 위 줄은 더블·스플릿·서렌더.
  - 더블·스플릿·서렌더는 **지금 할 수 있을 때만** 표시한다(불가능하면 비활성 대신 숨김). 하나도 없으면 히트·스탠드가 조작부 높이 전체를 차지한다.
- 스플릿 시 핸드를 2열 그리드로 나열한다(3~4핸드는 2×2). 카드 폭 `clamp(48px, 15vw, 72px)`, 겹침 58%(카드 5장 이상이면 68%). 활성 핸드는 금색 테두리로 표시한다.
- 새로 나온 카드에만 딜 애니메이션을 적용한다. 0.33초, 여러 장이면 165ms 간격.

### 6.1 딜러 공개 연출

엔진은 정산까지 한 번에 끝내고, 화면만 아래 순서로 따라간다(`src/main.ts` `playReveal`, 시간은 `src/ui/view.ts` `TIMING`).

1. 홀 카드가 공개되는 조작(스탠드·버스트·더블·서렌더·딜 직후 블랙잭·피크·이븐 머니 등) 직후, 홀 카드는 뒷면 그대로 대기: 550ms (딜 직후 바로 끝난 라운드는 카드가 다 깔리도록 1000ms).
2. 홀 카드를 살짝 들어 올렸다가 뒤집는다: 950ms. 뒤집는 동안 딜러 합계는 업카드 값 그대로이고, 다 뒤집은 뒤 갱신한다.
3. 딜러가 더 받을 카드가 있으면 450ms 쉬고, 한 장씩 800ms 간격으로 보여 준다(카드 애니메이션 0.45초).
4. 400ms 뒤 결과(배지, 이번 판 손익, 잔액)를 표시한다.

- 연출 중에는 메시지 줄에 "딜러 차례"를 표시하고 조작부는 비운다(조작 불가). 핸드 결과 배지는 숨긴다.
- 헤더 잔액은 연출이 끝날 때까지 **정산 전 값**(베팅·더블·스플릿·보험이 빠진 뒤, 반환 전)을 표시한다.
- 저장은 엔진 정산 직후 그대로 한다(연출 중 새로고침해도 결과는 확정).
- 건너뛰기(탭해서 빨리 감기)는 없다.
- 테이블은 딜러 라벨(합계)·딜러 카드·메시지·플레이어 영역을 따로 갱신한다. 애니메이션 클래스를 뺀 내용이 같으면 그 영역의 DOM을 다시 만들지 않는다. 그래서 연출 도중 토스트가 사라지거나, 설정 창을 닫거나, 합계 표시를 켜고 꺼도 진행 중인 뒤집기·딜 애니메이션이 처음부터 다시 시작되거나 끊기지 않는다.
- `safe-area-inset`을 반영하고, 홈 화면 추가용 메타 태그와 아이콘을 넣는다.

## 7. 구조

```
src/engine/   DOM 비의존 순수 로직 (테스트 대상)
  cards.ts    Card, handValue, isBlackjack
  shoe.ts     CardSource 인터페이스, Shoe(셔플/리셔플)
  rules.ts    Rules, DEFAULT_RULES
  game.ts     Game 상태 머신 (deal → insurance → player → settled)
src/ui/
  view.ts     테이블/조작부 HTML 렌더
  settings.ts 설정 다이얼로그
  storage.ts  localStorage
src/main.ts   이벤트 → Game 호출 → 다시 렌더
tests/        vitest. 카드 순서를 고정한 StackedShoe로 시나리오 검증
```

## 8. 검증

- `npm test`: 엔진 테스트 29개 + 화면 보조 함수 테스트 7개(`bankrollBeforePayout`, 영역별 렌더). 핸드 값, 배당(3:2/6:5), 피크, S17/H17, 더블, 스플릿(DAS, A 스플릿, 최대 핸드), 보험·이븐 머니(3:2/6:5 각각), 서렌더, 슈 리셔플을 다룬다.
- `npm run build`: `tsc --noEmit` 후 Vite 빌드.
- 수동: 390×844 헤드리스 Chromium에서 랜덤 액션으로 60라운드를 진행하고 스플릿 시나리오를 확인했다. 콘솔 에러는 없었다.
- 수동(6절 변경): 같은 환경에서 조작부, 스플릿 2열, 딜러 공개 연출을 시점별(300/900/1250/1500/2300ms) 스크린샷으로 확인했다.

## 9. 배포

- `.github/workflows/deploy.yml`: `main`에 푸시하면 테스트 → 빌드 → GitHub Pages 배포.
  - 액션은 Node 24 런타임 버전을 쓴다: `checkout@v6`, `setup-node@v6`, `upload-pages-artifact@v5`, `deploy-pages@v5`.
- 최초 1회 저장소 Settings → Pages → Source를 "GitHub Actions"로 설정해야 한다.
- `vite.config.ts`의 `base: './'`로 하위 경로(`/Stand-on-17/`)에서도 동작한다.
