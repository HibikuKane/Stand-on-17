## Q&A

### Q1. 어디서 돌릴 건가? (PHP 웹 / 브라우저 JS / CLI)

> 웹에서 바로 돌아가는 걸 원하니까(폰에서 부담없이 켜서 가지고 놀 수 있으면 좋겠음), 아마 또 타입스크립트라던가 기반으로 부탁할 듯...?

→ 브라우저에서 바로 돌아가는 TypeScript 앱. **모바일 우선**.

### Q2. 룰은 어디까지? (기본 / 더블·스플릿·보험·서렌더 / S17·H17 / 덱 수)

> 일단은 기존 블랙잭 기능만 있으면 좋겠는데... 더블 다운 스플릿 보험까지는 나도 있음 좋겠고, 서렌도 요즘 블랙잭으로써는 꽤 일반적인 확장 룰이려나?

→ 더블·스플릿·보험 확정. 서렌더는 질문 형태 → LLM이 "일반적"이라고 답하고 **포함(설정으로 끌 수 있게)**.

> 소프트 17이랑 하드17은 내가 아직 그 차이를 몰라서 설명부터 브리핑해주면 좋을 거 같음.
> 블랙잭 3:2...도 무슨 의미인지 알려주면 고맙겠고

→ 개념 설명 요청. 채팅으로 설명했고, 같은 내용을 게임 내 설정 화면의 "룰 설명"에도 넣음.

> 덱 갯수는... 음..... 설정 창 같은 곳에서 조정할 수 있어도 좋겠다는 생각은 드네.

→ 덱 수는 설정 화면에서 변경.

### Q3. 목적은? (플레이용 게임 / 전략·카운팅 시뮬레이터)

명시적 답변 없음. Q1의 "폰에서 부담없이 켜서 가지고 놀 수 있으면"에서 **플레이용**으로 해석.

### Q4. (PR 작성 시) 사양·의도 보존

> 리뷰는 GPT한테 부탁시켜볼 거니까 PR쪽에는 '이번 개발분량의 목적과 사양이 어떻게 되는지'도 설명할 수 있으면 좋을 거 같음
> 사양은 따로 디렉토리 하나 파서 영구파일로 보존하는 게 좋으려나
> 사양서 만드는게 귀찮더라도 내 의도(LLM이 어떤 질문을 했고 사용자가 어떤 대답을 했는지)를 보존하기 위한 폴더는 하나쯤 있어도 좋을 거 같네.

→ `docs/specs/`(사양서)와 `docs/intent-log/`(이 파일) 생성.

## 사용자가 명시하지 않아 LLM이 정한 것

리뷰 시 "요구사항"이 아니라 "구현자 판단"으로 봐야 하는 항목.

| 항목 | 정한 값 | 이유 |
|---|---|---|
| 프레임워크 | 없음 (Vite + 순수 TS + DOM) | 화면이 단순하고 폰에서 가볍게. 빌드 JS 약 16KB |
| S17/H17 기본값 | **S17** | 레포 이름 "Stand-on-17". 설정에서 H17로 변경 가능 |
| 블랙잭 배당 | 3:2 기본, 6:5 선택 가능 | 사용자가 3:2 의미를 물어서 비교용으로 6:5 추가 |
| 덱 수 기본값 / 선택지 | 6덱 / 1·2·4·6·8 | 카지노 일반값 |
| 서렌더 종류 | 레이트 서렌더 (딜러 피크 후), 기본 ON | 현재 가장 흔한 형태 |
| 딜러 피크 | 미국식 (A·10 업카드면 홀 카드 확인) | 일반적인 룰. 딜러 BJ면 더블·스플릿 전에 원금만 잃음 |
| 스플릿 | 최대 4핸드, 같은 **값**이면 가능(10·J 등), A 리스플릿 불가, A 스플릿은 한 장씩 | 일반적인 룰 |
| DAS | 기본 ON, 설정에서 OFF | 일반적인 룰 |
| 리셔플 | 슈 75% 소진 후 다음 라운드 전 | 일반적인 컷 카드 위치 |
| 21 도달 | 자동 스탠드 | 모바일 조작 편의 |
| 시작 자금 / 칩 | 1,000 / 10·50·100·500 | 임의 |
| 파산 시 | 1,000으로 다시 시작 버튼 | 임의 |
| 저장 | localStorage (잔액·베팅·설정) | 서버 없음 |
| UI 언어 | 한국어 | 사용자가 한국어 사용 |
| 배포 | GitHub Pages (main 푸시 시) | "폰에서 켜기"를 위해. 사용자 승인 전 제안 단계 |

## 리뷰 반영 (PR #1, GPT 리뷰)

사용자가 GPT에게 리뷰를 맡겼고, 그 결과 P2 지적 2건이 나왔다.

> 히히히 GPT한테 리뷰 남겨두게 했따
> 리뷰 확인해줄래?

| 지적 | 판단 | 조치 |
|---|---|---|
| 라운드 도중 설정을 바꾸면 베팅이 빠진 잔액이 저장됨 (1,000 → 990) | 타당. 브라우저에서 재현 확인 | 잔액은 마지막 라운드 경계 값만 저장 |
| 6:5에서 "블랙잭 + 보험"을 "이븐 머니(1:1 확정)"로 표시하지만 실제로는 +70 | 타당. 테스트로 재현 확인 | GPT가 제시한 두 가지 안 중 **진짜 이븐 머니(별도 정산 액션)**를 선택 (LLM 판단) |

이븐 머니 쪽을 고른 이유: 카지노의 이븐 머니는 "딜러 확인 없이 1:1 즉시 지급"이 정의이고, 사용자에게 설명한 내용과도 일치하기 때문이다. 6:5에서 라벨만 "보험"으로 바꾸면 6:5 테이블에서 이븐 머니라는 선택지 자체가 사라진다.
