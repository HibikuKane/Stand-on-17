## 확인 결과: Node 20 경고

배포 런 #2(build 잡) 로그 마지막 줄:

```
Node.js 20 is deprecated. The following actions target Node.js 20 but are being forced to run on Node.js 24: actions/checkout@v4, actions/setup-node@v4, actions/upload-artifact@v4.
```

- 배포 자체는 성공. 런타임이 Node 24로 강제되고 있다는 경고.
- `upload-artifact@v4`는 `upload-pages-artifact@v3`가 내부에서 쓴다. `deploy-pages@v4`도 `action.yml`이 `node20`.
- 각 액션의 `action.yml`을 직접 읽어 `node24`인 버전으로 올림: `checkout@v6`, `setup-node@v6`, `upload-pages-artifact@v5`(내부 upload-artifact v7.0.0), `deploy-pages@v5`.
- 워크플로 `node-version: 22`(빌드에 쓰는 Node)는 경고와 무관해서 그대로 둠.

## 사용자가 명시하지 않아 에이전트가 정한 것

| 항목 | 정한 값 | 이유 |
|---|---|---|
| 액션 메이저 버전 | checkout v6, setup-node v6 (v5도 node24) | 최신 메이저. v5→v6 사이 이 워크플로에 영향 있는 입력 변경 없음(`cache: npm` 명시 중). 실제 CI 실행으로는 아직 확인 못 함 |
| 스플릿 레이아웃 | 2열 그리드(3~4핸드는 2×2), 카드 폭 `clamp(48px, 15vw, 72px)`(기존 `clamp(40px, 11vw, 60px)`), 겹침 58%(5장 이상 68%) | 가로로 한 줄 나열하면 핸드가 늘수록 폭이 줄어든다. 2열이면 390px 폭에서 핸드당 ~170px 확보, 카드 5장도 들어감 |
| 조작부 높이 | 플레이 중 152px 고정. 히트·스탠드가 남은 높이를 다 채움(보조 버튼 있을 때 약 92px, 없을 때 152px) | "상하폭이 좁아 보임" → 터치 영역을 위로 넓힘. 상태가 바뀌어도 높이가 안 튀게 고정 |
| 보조 버튼 위치 | 히트·스탠드 **위** 줄 (기존: 아래 줄) | 히트·스탠드를 엄지 위치(하단)에 고정. 더블·서렌더처럼 되돌릴 수 없는 액션은 한 번 더 손을 뻗게 해서 오탭을 줄임 |
| 보조 버튼 표시 | 스플릿뿐 아니라 더블·서렌더도 가능할 때만 표시 | 요청은 스플릿만 예로 들었지만 같은 이유(불가능한 버튼이 자리 차지)가 더블·서렌더에도 해당 |
| 플레이어 카드 속도 | 0.28s→0.33s, 간격 140→165ms (약 18% 느리게) | 요청 "10~20퍼" 범위 |
| 딜러 공개 타이밍 | 대기 550ms(딜 직후 1000ms) → 들어 올리며 뒤집기 950ms → 450ms → 추가 카드 800ms 간격(0.45s 애니) → 결과까지 400ms | 기존엔 뒤집기 연출 없이 즉시 앞면 + 추가 카드 140ms 간격. 요청 "2~3배속"을 기준으로 추가 카드 간격을 약 5배, 뒤집기는 새로 추가 |
| 연출 중 결과 숨김 | 합계는 뒤집기 끝난 뒤 갱신, 배지·손익·헤더 잔액은 연출 끝에 표시 | 결과가 먼저 보이면 긴장감이 사라짐 |
| 건너뛰기 | 없음 | 요청은 "느리게". 반복 플레이가 지루하면 후속으로 탭 스킵 추가 가능 |
| 연출 중 저장 | 엔진 정산 직후 바로 저장 | 연출 중 새로고침으로 결과를 피할 수 없게 |
