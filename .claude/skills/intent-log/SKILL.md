# intent-log: 의도 기록

`docs/intent-log/`는 사용자 의도의 SoT다. 사양서는 다듬어진 결과물이고, 이건 원재료다.

## 작업 시작 시

1. `docs/intent-log/`에서 이번 작업과 관련된 파일을 찾아 읽는다.
2. 이미 답이 있는 질문은 다시 묻지 않는다. 기록과 다른 지시가 오면 "이전 결정(<파일>#<항목>)과 다른데 이걸로 바꿀까요?"라고 확인한다.

## 기록 절차

1. 파일 결정
   - 새 작업 단위: `docs/intent-log/YYYY-MM-DD-<주제>.md` 새로 만든다 (날짜는 오늘).
   - 같은 작업의 후속 세션(리뷰 반영 등): 기존 파일 **끝에 섹션을 추가**한다. 위쪽 내용은 고치지 않는다.
2. 아래 템플릿으로 쓴다.
3. 사양서·PR과 서로 링크한다.

## 템플릿

```markdown
# YYYY-MM-DD <주제>

사양서: [`specs/<file>.md`](../specs/<file>.md)
작성: <모델 계열> (<도구>)

## 시작

> <사용자의 첫 요청 원문>

## Q&A

### Q1. <에이전트가 한 질문 요지>

> <사용자 답변 원문. 오타·말투 그대로>

→ <에이전트가 이 답을 어떻게 해석·반영했는지 한 줄>

### Q2. ...

(질문했는데 답이 없었다면 "명시적 답변 없음" + 어떻게 해석했는지)

## 사용자가 명시하지 않아 에이전트가 정한 것

| 항목 | 정한 값 | 이유 |
|---|---|---|

## 결과

- 브랜치 / PR 링크
- 사양서 링크
```

## 원칙

- 사용자 답변은 **인용 블록(`>`)으로 원문 그대로**. 요약·교정 금지.
- 해석(`→`)과 원문을 섞지 않는다.
- "에이전트가 정한 것" 표는 빠짐없이. 사소해 보여도 사용자가 말하지 않은 숫자·기본값·라이브러리 선택은 전부 여기 들어간다.
- 리뷰 반영 시: `## 리뷰 반영 (PR #N, <리뷰어 모델>)` 섹션을 추가하고 `| 지적 | 판단 | 조치 |` 표로 남긴다.
