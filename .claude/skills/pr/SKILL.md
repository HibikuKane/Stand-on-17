# pr: PR 본문 작성

사용자는 다른 모델에게 리뷰를 맡긴다. 리뷰어가 **코드를 열기 전에** 목적·범위·사양을 알 수 있게 쓴다.

## PR 전 체크

- [ ] `npm test && npm run build` 통과
- [ ] 동작 변경이 있으면 `docs/specs/` 갱신 (`spec` 스킬)
- [ ] 이번 세션의 Q&A·가정을 `docs/intent-log/`에 기록 (`intent-log` 스킬)
- [ ] 목적 하나에 PR 하나. 범위 밖 수정이 섞였으면 빼거나 별도 PR로

## 본문

[`.github/pull_request_template.md`](../../../.github/pull_request_template.md)를 채운다. 섹션을 지우지 말고, 해당 없으면 "해당 없음"이라고 쓴다.

작성 요령:
- **첫 줄 작성자 표기**: `> 🤖 작성: <Claude|GPT|Gemini> (<도구>)`. 구체적인 모델 버전 ID는 쓰지 않는다.
- **변경 범위**는 "한 것"보다 **"안 한 것"**이 중요하다. 리뷰어가 의도적으로 남겨둔 부분을 버그로 지적하지 않게.
- **에이전트 판단**은 intent-log의 표를 링크하고, 그중 리뷰어가 꼭 봐야 할 1~3개만 본문에 올린다.
- **검증**에는 실제로 돌린 명령만. 안 돌린 건 "미실행"이라고 쓴다.
- 제목: 한국어, 무엇을 바꾸는지 한 줄.

## 코멘트·Issue·Discussion

PR 본문이 아니어도 에이전트가 GitHub에 쓰는 글은 **전부** 첫 줄에 작성자 표기를 단다.

```
> 🤖 작성: Claude (Claude Code)

<본문>
```
